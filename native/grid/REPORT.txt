Behavior details
- Row strings are held once; frame work is bounded by visible rows/columns.
  Only one cell editor is allocated. FrameStats retains at most 1,200 samples.
- Edits/sorts emit requests; they do not mutate caller-supplied row values or
  issue SQL. Context menus, inspector, Quick Look and cell popups emit hooks.
  COPY_MENU plus activate_menu cover Electron's built-in copy commands; caller
  supplies extra items and native menu presentation.
- DEFAULT is represented by sparse per-cell metadata, keeping None as SQL NULL.
  Unchanged empty NULL/DEFAULT editors do not emit edits. Literal NULL stays
  a string. SQL NULL/DEFAULT actions belong to the caller's menu handling.
- Copy includes hidden columns. Single-row plus active-column selection copies
  a cell; other selections copy rows in sorted order. TSV is intentionally not
  quoted and paste strips every CR but just one trailing LF.
- GPUI dispatch tests caught and fixed automatic scroller focus stealing focus
  from double-click editors, the Base Root consuming Tab, and different CR/LF
  handling for HTML input/textarea paste. Thai/emoji IME, native Edit-menu copy,
  Tab/Enter commits, Esc, multiline blur, external resize drags, popup anchors,
  context hooks and 100k x 30 render bounds all pass.
- Electron does not explicitly implement PageUp/PageDown/Home/End/non-editing
  Tab; these requested keys are added. Existing arrow/anchor behavior remains
  identical, including repeated Shift+Arrow using the original anchor and
  arrows including hidden column indices.
- Modified rows do not get a whole-row tint in Electron. MOD_CELL colors changed
  cells; MOD is exported for the parent's dirty-state UI. NEW/DEL override row
  selection while the active-cell outline remains visible.
